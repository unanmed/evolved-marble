<objective>
Write the COMPLETE physics-system type contract — all numeric enums and `I*` interfaces — and stop at the mandatory human type-design review gate before any implementation. This is round 1 of the project's mandatory two-round planning convention (PROJECT.md / AGENTS.md): **round 1 plans type declarations ONLY**.

**This plan contains NO implementation logic.** `src/physics/types.ts` declares enums and interfaces only — no Rapier calls, no damage arithmetic, no class, no constants. The compound-body registration, the contact→event pipeline, the damage/armor math, and the fixed-tick driver are Wave-2 implementation work, planned in round 2 AFTER the user approves this contract. Do not read the absence of those plans as an omission.

Purpose: this file is the stable contract that Phase 3 (control: forces/torque) and Phase 5 (render: unit state) will consume, so its shape is the phase's highest-value design artifact.
Output: `src/physics/types.ts` (enums + interfaces, JSDoc'd), `tests/physics/types.test.ts` (numeric-enum + alias assertions), and a resolved blocking-human design-approval checkpoint.

Contract shape carried from the locked decisions (present at the gate for confirmation):
- **D-03/D-05:** the type layer models a unit as ONE rigid body with separate body/weapon/armor colliders carrying their own masses — the spec type supplies those numbers.
- **D-04:** part identity is `collider handle → {unitId, part}`; `ColliderPart` is the numeric part enum. No per-unit collision-group bits appear anywhere.
- **D-06:** geometry is calibratable and centralized — described by `IPhysicsGeometry` (values live in a Wave-2 constants file, each top-level `const` JSDoc'd).
- **D-07:** the physics layer owns the Rapier world, registers units by id, and holds the id→body map; the contract therefore exposes ids/primitives only and never owns or references `Unit`.
- **D-08/D-09/D-14:** contacts become typed part-tagged events; damage is computed by physics and emitted with FINAL numbers (`damage`/`damageReduced`); applying to a `Unit` is the caller's job.
- **D-10:** one tick = one physics step, fixed `dt = 1/60 s`, decoupled from rendering.
- **D-11:** armor reduction uses the sign-consistent `B_A = 破甲比率` (OQ-1 RESOLVED). The formula itself is Wave-2; only the event fields that carry its inputs/outputs are declared here.
- **D-13/OQ-4:** weapon↔weapon and body↔body yield no damage; the specific armor collider hit determines `armorKind`; weapon↔armor applies reduction, weapon↔body does not.
- The jitter RNG is the existing shared `IRng` (`src/common/rng.ts` `sampleNormal`, σ = mean/20) — injected into the Wave-2 `PhysicsWorld`, NOT declared here and NOT re-implemented (AGENTS §9).
- **Scope boundary (deliberate, not an omission):** the phase-level contract is `IPhysicsWorld`. No `IBattleSim` / battle-settlement type is created in Phase 2 — battle triggering, armies, and post-battle settlement belong to Phase 4 (王国系统). Confirm this boundary at the gate.
</objective>

Numeric enum (every member an integer literal; string enums forbidden):
- `ColliderPart` — `Body = 0`, `Weapon = 1`, `Armor = 2`. This is the part tag carried by `Map<colliderHandle, {unitId, part}>` (D-04). JSDoc each member (本体 / 武器 / 防具).

Interfaces (JSDoc on EVERY member; definitional fields `readonly`):
- `IUnitPhysicsSpec` — the numbers-only registration input (D-07/A5). Given that physics never touches a `Unit`, the caller supplies these numbers:
  - `readonly unitId: number` — the id the physics layer keys everything by.
  - `readonly x: number` / `readonly y: number` — spawn position.
  - `readonly mass: number` — the body collider's mass, sourced by the caller from `Unit.getAttribute(AttributeKind.Mass)` (D-05).
  - `readonly attack: number` — `A_A`, base attack.
  - `readonly weaponRatio: number` — `P_A`, weapon ratio.
  - `readonly defense: number` — `A_D`, base defense.
  - `readonly armorRatio: number` — `P_D`, armor ratio.
  - `readonly weapon: IWeaponDef | null` — the equipped weapon definition (its `mass`, `attackRatio` `W_A`, and `penetration` table are used); an absent weapon is `null` (absent OBJECT → `null`, AGENTS §8). Do NOT make this field optional-with-literal-undefined.
  - `readonly armors: readonly IArmorDef[]` — every equipped armor def (each yields one armor collider bound to its `ArmorKind`, D-13/OQ-4); an unarmored unit supplies an empty array (absent COLLECTION → empty, no `null`).
- `IUnitState` — the numeric kinematic readout for control (Phase 3) and render (Phase 5): `readonly x: number`, `readonly y: number`, `readonly angle: number`, `readonly vx: number`, `readonly vy: number`, `readonly angularVelocity: number`. JSDoc each (angle in radians; velocities in Rapier's per-second units).
- `IContactEvent` — a typed, part-tagged contact (PHYS-02): `readonly unitAId: number`, `readonly partA: ColliderPart`, `readonly unitBId: number`, `readonly partB: ColliderPart`. JSDoc: the pair is UNORDERED (A/B are not attacker/defender); only `started` transitions are emitted (D-08); colliders on the same unit never produce an event (Rapier broad phase — research Pitfall 4).
- `IDamageEvent` — a typed, part-tagged damage event carrying FINAL numbers (D-09/D-14; OQ-3 RESOLVED):
  - `readonly attackerId: number` (the weapon owner) / `readonly defenderId: number`.
  - `readonly attackerPart: ColliderPart` — the attacking collider's part (always `Weapon`); `readonly defenderPart: ColliderPart` — the struck collider's part (`Body` or `Armor`).
  - `readonly weaponKind?: WeaponKind` — optional literal (absent → `undefined`, D-11).
  - `readonly armorKind?: ArmorKind` — optional literal; `undefined` when the body was struck (no reduction), present when an armor collider was struck (D-13/OQ-4).
  - `readonly deltaV: number` — the collision-normal relative velocity difference (`Δv`, m/s) computed from PRE-step velocities + the `contactPair().normal()`.
  - `readonly damageMean: number` — the pre-jitter mean `D̄_R = max[A_A·P_A·W_A·(√Δv − 1), 0]`.
  - `readonly damage: number` — the final applied damage `D` (post-jitter, post-reduction).
  - `readonly damageReduced: number` — the reduction `ΔD` applied for an armor hit (`0` when the body was struck).
- `IPhysicsTickResult` — the value returned by one tick (PHYS-02/03): `readonly contacts: readonly IContactEvent[]` and `readonly damages: readonly IDamageEvent[]`. This is how both typed event families reach the caller; damage events require at least one `Weapon` collider with a differing owner (D-13; weapon↔weapon and body↔body yield no damage).
- `IPhysicsGeometry` — the calibratable shape numbers (D-06): `readonly bodyRadius: number` (unit circle), `readonly weaponHalfLength: number` and `readonly weaponRadius: number` (weapon capsule), `readonly weaponOffsetX: number` (weapon local offset from the body centre), `readonly armorRadius: number` (armor circle). JSDoc each as calibratable defaults (D-06); the concrete numbers live in the Wave-2 constants file.
- `IPhysicsConfig` — construction parameters: `readonly dt: number` (the fixed simulation step in seconds; production value is the locked `1/60` per D-10) and `readonly geometry: IPhysicsGeometry`. JSDoc both.
- `IPhysicsWorld` — the physics-system contract (D-07). Methods, all JSDoc'd:
  - `registerUnit(spec: IUnitPhysicsSpec): void` — create ONE compound body (body/weapon/armor colliders with per-collider mass and fixed local offsets, D-03/D-05) and index every collider handle.
  - `removeUnit(unitId: number): void` — remove the body and its colliders AND delete every handle-map entry for it (handle reuse hazard — research Pitfall 3).
  - `hasUnit(unitId: number): boolean`.
  - `applyForce(unitId: number, forceX: number, forceY: number): void` — the linear actuator control (Phase 3) drives units with.
  - `applyTorque(unitId: number, torque: number): void` — the rotational actuator.
  - `getUnitState(unitId: number): IUnitState | null` — the numeric kinematic readout; `null` for an unknown id (absent OBJECT → `null`, AGENTS §8).
  - `tick(): IPhysicsTickResult` — advance exactly one fixed step and return the typed events (D-10).
  - `dispose(): void` — free the Rapier world and event queue (research Pitfall 12).

Do NOT add: getters/setters, a `PhysicsWorld` class, any top-level `const` (no values yet), a factory, string enums, a literal type union with `null` for any absent-literal field (use optional/`undefined`), a per-unit collision-group type, an `IBattleSim`, or any Rapier type in a signature. Keep it a pure declaration module. Keep other comments sparse.
