Private state (each field JSDoc'd — AGENTS §4; use `#` private fields):
- the `RAPIER.World` and `RAPIER.EventQueue`;
- `#config: IPhysicsConfig` and `#rng: IRng`;
- `#bodies: Map<number, RAPIER.RigidBody>` — unit id → its compound body;
- `#specs: Map<number, IUnitPhysicsSpec>` — retained numbers for later damage math (plan 02-06);
- `#colliders: Map<number, readonly RAPIER.Collider[]>` — unit id → its colliders (used to purge the index on removal);
- `#index: Map<number, { unitId: number; part: ColliderPart; weaponKind?: WeaponKind; armorKind?: ArmorKind }>` — collider handle → part tag (D-04);
- `#preVelocities: Map<number, { vx: number; vy: number }>` — per-unit pre-step velocity snapshot placeholder (populated in plan 02-06).

Public members (ONLY those on `IPhysicsWorld` — AGENTS §5):
- `registerUnit(spec)`: if `#bodies.has(spec.unitId)` throw an Error naming the duplicate id. Create the body via `RigidBodyDesc.dynamic().setTranslation(spec.x, spec.y)`. Create the body collider: `ColliderDesc.ball(geometry.bodyRadius)` with `.setMass(spec.mass)` and `.setActiveEvents(COLLISION_EVENTS)`. If `spec.weapon` is not `null`, create a `ColliderDesc.capsule(geometry.weaponHalfLength, geometry.weaponRadius)` with `.setTranslation(geometry.weaponOffsetX, 0)`, `.setMass(spec.weapon.mass)`, `.setActiveEvents(COLLISION_EVENTS)`. For each entry of `spec.armors`, create a `ColliderDesc.ball(geometry.armorRadius)` with `.setMass(armor.mass)` and `.setActiveEvents(COLLISION_EVENTS)`. Register every created collider's `handle` into `#index` with its `{unitId, part}` and, where applicable, `weaponKind: spec.weapon.id` or `armorKind: armor.id` (D-13/OQ-4: each armor collider carries its own kind). Store the body, spec, and collider list in the maps.
- `removeUnit(unitId)`: no-op if unknown. Delete every `#index` entry for the unit's colliders FIRST (iterate the stored collider list and `.delete(collider.handle)`), then `#world.removeRigidBody(body)` (which frees the attached colliders), then delete the body/spec/collider/pre-velocity map entries — so a later `createCollider` that reuses a handle cannot mis-tag (research Pitfall 3). Do NOT call `world.removeCollider(...)` separately for colliders owned by a removed body.
- `hasUnit(unitId)`: `#bodies.has(unitId)`.
- `applyForce(unitId, forceX, forceY)`: unknown id is a no-op; otherwise `body.addForce({ x: forceX, y: forceY }, true)`.
- `applyTorque(unitId, torque)`: unknown id is a no-op; otherwise `body.addTorque(torque, true)`.
- `getUnitState(unitId)`: `null` for unknown id (absent object → null, AGENTS §8); otherwise read `translation()`/`rotation()`/`linvel()`/`angvel()` and return `{ x, y, angle, vx, vy, angularVelocity }` (all finite; the 2D `rotation()` is the angle in radians).
- `tick()`: advance exactly one fixed step. Iterate every registered body and `resetForces(false)` + `resetTorques(false)` is done AFTER the step (see below). Call `#world.step(#eventQueue)`, then for each body clear the per-tick actuators (`body.resetForces(false); body.resetTorques(false);`) so a force applied before `tick()` is consumed by exactly this step and must be re-applied next tick (matches the per-tick control cadence). Return `{ contacts: [], damages: [] }` — this task establishes the fixed-step driver (PHYS-05); the contact pipeline is added in plan 02-05 and the damage pipeline in plan 02-06. Do NOT consult `Date.now()` or any wall-clock.
- `dispose()`: `#world.free()` and `#eventQueue.free()`, then clear all maps.

No getters/setters (AGENTS §12). No public helper methods. Private helper methods, if any, must carry JSDoc and be `#`-prefixed. Keep other comments sparse.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller numbers → engine | `IUnitPhysicsSpec` numeric input crosses into Rapier body/collider construction; degenerate values (zero mass, NaN coordinates) would corrupt the simulation. |
| WASM heap → Node process | Rapier allocates WASM memory for the `World`, bodies, colliders, and `EventQueue`; it must be released explicitly. |
| engine handles → part index | Collider handles are integers that Rapier REUSES after removal; a stale index entry would mis-attribute a later collider. |
| (no network / no secrets) | Headless in-process module; no I/O beyond the already-gated dependency. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-02-09 | Tampering (data integrity) | collider-handle index lifetime | high | mitigate | `removeUnit` deletes every index entry for the unit BEFORE freeing its colliders, so a reused handle cannot resolve to a stale tag; the re-registration test exercises this. |
| T-02-10 | Denial of Service (test process) | unfreed `World`/`EventQueue` | medium | mitigate | `dispose()` frees both WASM objects; every test calls it in `afterEach` (research Pitfall 12). |
