<objective>
Close the single failed Phase-2 must-have truth: unit-level `InteractionGroups` (D-27) must keep every distinct unit pair colliding beyond 16 concurrent units rather than silently aliasing membership bits every 16 entity ids (VERIFICATION.md gap / review CR-01).

Purpose: the product's core is multi-faction battles at 10v10+ (20+ units); the current `(entityId - 1) % GROUP_COUNT` allocator makes ids `(1,17),(2,18),(3,19),(4,20)` ghost through each other. Replace the modulo alias with a deterministic **live-unit pool** of distinct membership masks, release masks on `despawn`, fail loud on exhaustion, and re-seed the pool on `restore` (folding in review WR-03).

Output: a corrected `composite.ts` allocator (with widened multi-bit membership so the 20-unit target regime is covered), updated single-source group constants, `BattleSim.restore` rehydration, and the `>16`-concurrent-unit regression suite.
