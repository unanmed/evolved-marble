<objective>
Repair the Phase-1 automated-verification harness so every later plan can be verified. This is the "Wave 0" setup plan (frontmatter `wave: 0`); the project's type-first gate begins in plan 01-02.

The unit system is pure in-process TypeScript with no external runtime dependency, so the only tooling that must work is Vitest (runner + `@` alias) and `tsc` (typecheck). Two independent defects block the harness today: (a) `vitest.config.ts` is a leftover from the deleted prior version — its `setupFiles` points at a nonexistent physics setup file and it defines no `resolve.alias`, so any `@/units/...` import fails under Vitest; (b) `tsconfig.json` `include: ["src"]` never typechecks `tests/` and references a `tsconfig.sim.json` that does not exist.

Purpose: without this repair, `pnpm test` exits 1 (no matching test files / missing setup module) and `pnpm typecheck` cannot see test files — the Nyquist validation contract (01-VALIDATION.md) cannot run.
Output: a repaired `vitest.config.ts`, a repaired `tsconfig.json`, and a minimal `tests/units/` smoke test so `pnpm test` and `pnpm typecheck` are green before type work starts.

Known limitation recorded here (NOT repaired this phase): `pnpm lint` is non-functional because `typescript-eslint@8.x` refuses to import under TypeScript 7.0 (the compiler ships no JS API). This is an external toolchain incompatibility that affects no Phase-1 requirement; the ASCII-convention rules it would enforce are not lint rules in this project anyway. Lint is out of scope for Phase 1 and is surfaced to the user as a known limitation rather than silently dropped.
</objective>
