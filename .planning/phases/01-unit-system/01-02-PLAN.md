<objective>
Produce the COMPLETE unit-system type contract — all enums and `I*` interfaces — and stop at the mandatory human review gate before any implementation. This is the project's type-first gate: per ROADMAP.md and AGENTS.md, no implementation may begin until the user has reviewed and approved this interface design.

This plan is **type declarations only**: `src/units/types.ts` must contain enums and interfaces, no algorithms. Every derived numeric value later reads through the single accessor `getAttribute(kind: AttributeKind): number` (decision D-04); no getter/setter exists anywhere (D-05); all unit-system types live in this one file (D-10).

Purpose: this file is the stable contract that Phases 2 (physics), 3 (control) and 5 (render) will import, so its shape is the phase's highest-value design artifact.
Output: `src/units/types.ts` (enums + interfaces, JSDoc'd), `tests/units/types.test.ts` (numeric-enum + alias assertions), and a resolved design-approval checkpoint.

Flagged design gaps to surface at the review gate (do NOT silently resolve):
- The phase goal/REQUIREMENTS say "17 项属性", but the spec and UNIT-01 enumerate exactly 16; no 17th is invented. The 13 numeric kinds go through `getAttribute`; 职业/装备/加成 are non-numeric and get dedicated accessors.
- Growth notation (spec: "基础攻击力每级增加 10L 点" vs defense "每级增加 6 点") is interpreted linearly as `stat(L) = base + k·(L-1)`; the type layer must not bake in a shape — it only declares `IClassDef` fields.
- The spec never states how 生命上限 grows per level; a per-class `maxHpGrowth` field is declared (value chosen in plan 01-03).
- Experience reset on level-up (0 vs remainder) is not specified; declared via the `IUnit` progression methods only.
</objective>

Create `src/units/types.ts` containing ONLY type declarations (numeric enums + interfaces) with JSDoc as required by AGENTS.md conventions #3, #4, #6. No functions, no classes, no constants with logic. Import nothing.

Numeric enums (every member must be an integer literal; string enums are forbidden):
- `AttributeKind` — the numeric attributes readable through `getAttribute`, with explicit integer values: `Health=0`, `MaxHealth=1`, `Level=2`, `Experience=3`, `ExperienceRatio=4`, `AttackExpRatio=5`, `DefenseExpRatio=6`, `ControlLevel=7`, `Attack=8`, `Defense=9`, `WeaponRatio=10`, `ArmorRatio=11`, `Mass=12`. (13 members; 加成/装备/职业 are non-numeric and are exposed via `IUnit` methods, not this enum.)
- `ClassKind` — `Swordsman=0`, `Archer=1`, `Berserker=2`, `Hammer=3`, `Knight=4`, `SwordShield=5`, `Spearman=6` (7 members). JSDoc each member with its Chinese class name.
- `WeaponKind` — `Longsword=0`, `Shortsword=1`, `Axe=2`, `Hammer=3`, `Bow=4`, `Spear=5` (6 members). JSDoc each with its Chinese weapon name.
- `ArmorKind` — `Helmet=0`, `Shield=1` (2 members). JSDoc each with its Chinese armor name.
- `SkillKind` — `ArrowStorm=0`, `Charge=1`, `Spin=2` (the three named skills 万箭齐发/冲锋/旋转).
- `EquipmentKind` — `Weapon=0`, `Armor=1` — discriminates the slot of an `IEquipment` entry.
- `ModifierMode` — `Flat=0`, `Multiplicative=1` — how an `IModifier` combines with a base value.

Interfaces (JSDoc on EVERY member; all fields `readonly` where they are immutable definitions):
- `ISpawnAttributes` — the 7 attributes rolled at spawn: `maxHp`, `controlLevel`, `attack`, `defense`, `weaponRatio`, `armorRatio`, `mass` (all `number`). JSDoc stating these are the 7 normal-distributed attributes.
- `IEquipment` — one equipped item: `kind: EquipmentKind`, `weapon: WeaponKind | null`, `armor: ArmorKind | null`. JSDoc: exactly one of `weapon`/`armor` is non-null, selected by `kind`.
- `IModifier` — a bonus: `kind: AttributeKind` (which attribute it affects), `mode: ModifierMode`, `value: number`. JSDoc describing flat vs multiplicative application.
- `IUnlockEntry` — a level-gated grant: `level: number`, `equipment: readonly IEquipment[]`, `skills: readonly SkillKind[]`. JSDoc: empty arrays when that level grants nothing of that type (狂战士 level 4 grants a second axe; level 6 grants the Charge skill).
- `IClassDef` — a class definition: `id: ClassKind`, `name: string`, `maxHp: number`, `attack: number`, `defense: number`, `weaponRatio: number`, `armorRatio: number`, `mass: number`, `experienceRatio: number`, `attackExpRatio: number`, `defenseExpRatio: number`, `attackGrowth: number`, `defenseGrowth: number`, `maxHpGrowth: number`, `initialEquipment: readonly IEquipment[]`, `unlocks: readonly IUnlockEntry[]`. JSDoc each field (base values are the level-1 values; growth fields are per-level increments).
- `IWeaponDef` — a weapon definition: `id: WeaponKind`, `name: string`, `mass: number`, `attackRatio: number`, `penetration: Readonly<Record<ArmorKind, number>>`. JSDoc: `penetration` is indexed by `ArmorKind` so the weapon×armor lookup is total and type-checked.
- `IArmorDef` — an armor definition: `id: ArmorKind`, `name: string`, `mass: number`, `defenseRatio: number`.
- `IRng` — the injectable randomness source: one method `next(): number` documented as returning a uniform value in `[0, 1)`. (No `normal()` method — Box–Muller lives in `rng.ts` so test stubs stay trivial.)
- `IUnit` — the core contract. Members (all methods, no accessors):
  - `getAttribute(kind: AttributeKind): number` — the single numeric read path; JSDoc: stored values returned directly, level-derived values computed on demand.
  - `getClass(): ClassKind`
  - `getEquipment(): readonly IEquipment[]`
  - `getModifiers(): readonly IModifier[]`
  - `getSkills(): readonly SkillKind[]` — the skills the unit has learned via level unlocks.
  - `takeDamage(amount: number): void` — reduces health (used to make the level-up health-restore observable).
  - `isAlive(): boolean` — false once health reaches zero.
  - `gainAttackExperience(damageDealt: number): void`
  - `gainDefenseExperience(damageReduced: number): void`
  - `gainKillExperience(enemyLevel: number): void`

Do NOT add: getters/setters, a `Unit` class, any `const` (no data yet), a factory, string enums, or any method not listed above. Keep it a pure declaration module.
