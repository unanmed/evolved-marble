<objective>
Produce the COMPLETE unit-system type contract — all enums and `I*` interfaces — and stop at the mandatory human review gate before any implementation. This is the project's type-first gate: per ROADMAP.md and AGENTS.md, no implementation may begin until the user has reviewed and approved this interface design.

This plan is **type declarations only**: `src/units/types.ts` must contain enums and interfaces, no algorithms. Every derived numeric value later reads through the single accessor `getAttribute(kind: AttributeKind): number` (decision D-04); no getter/setter exists anywhere (D-05); all unit-system types live in this one file (D-10), EXCEPT the generic, reusable `IRng` randomness interface, which lives in `src/common/types.ts` (D-07/D-09/D-10) and is re-exported from `src/units/types.ts` for a single import path. Missing values follow the project convention (D-11): an absent OBJECT reference is `null`, an absent LITERAL (number/enum/boolean/string) is optional/`undefined` — so `IEquipment.weapon`/`armor` are optional enum fields, not `| null`. Each unit carries a display name readable via `getName()` (D-12). Equipment is modeled as a list (weapon/armor entries carrying a kind), bonuses as an `IModifier` modifier list, with the unlock table deciding when equipment/skills are granted (D-06).

Purpose: this file is the stable contract that Phases 2 (physics), 3 (control) and 5 (render) will import, so its shape is the phase's highest-value design artifact.
Output: `src/units/types.ts` (enums + interfaces, JSDoc'd), `src/common/types.ts` (the shared `IRng` interface), `tests/units/types.test.ts` (numeric-enum + alias assertions), and a resolved design-approval checkpoint.

Design decisions now RESOLVED and carried into the type layer (present at the review gate for confirmation; OQ-1…OQ-7):
- Attribute count is **decided (OQ-1 RESOLVED): 16, not 17**. The 16 enumerated attributes are canonical; the goal's former "17 项属性" was a counting error, already reconciled in ROADMAP/PROJECT/CONTEXT. The 13 numeric kinds go through `getAttribute`; 职业/装备/加成 are non-numeric and get dedicated accessors. Do NOT invent a 17th attribute.
- Growth shape is **decided (OQ-2 RESOLVED)**: attack-class growth is level-scaling (`k·L` — the per-level increment scales with the current level), while defense-class growth is a FLAT per-level `+6`-style constant (防御 is a percentage damage-reduction stat; a `6L` curve would over-scale late game). The type layer only declares `IClassDef` fields — it must NOT bake in a shape; the shape lives in `getAttribute` (plan 01-04).
- 生命上限 growth is **decided (OQ-3 RESOLVED)**: a per-class `maxHpGrowth` field is declared and given a sensible calibratable default in plan 01-03; on level-up `hp += maxHpGrowth`.
- Experience overflow is **decided (OQ-4 RESOLVED)**: on level-up the threshold is subtracted and the surplus carried, looping so one gain can trigger multiple level-ups; declared via the `IUnit` progression methods only.
- Equipment mass is **decided (OQ-6 RESOLVED)**: unit `质量` is body mass only; weapons/armors carry their own mass (physics sums them later).
- Skill-less classes are **decided (OQ-7 RESOLVED)**: a class with no skill listed in the spec gets an empty skill set (equipment unlocks only).
- Missing-value convention is **decided (D-11, mandatory)**: an absent OBJECT reference is `null`; an absent LITERAL (number/enum/boolean/string) is optional/`undefined`. Concretely `IEquipment.weapon`/`armor` are optional enum fields (`weapon?: WeaponKind` / `armor?: ArmorKind`), never `| null`; the audit found no other literal-typed nullable field in this contract (object-typed nullable fields, if any appear later, stay `null`).
- Per-unit name is **decided (D-12)**: every unit carries a name, determined at spawn time and read through `IUnit.getName(): string` (a dedicated method, no getter). The name is stored at construction; `spawnUnit` supplies a `<class name>#<running index>` value, and a directly-constructed `Unit` falls back to its class name.
- Randomness source location is **decided (D-07/D-09/D-10)**: `IRng` is a simple, generic abstraction reused by other systems, so it lives in `src/common/types.ts` (not `src/units/types.ts`); its default implementation and the Box–Muller helper (`MathRng`, `sampleNormal`) live in `src/common/rng.ts`. `src/units/types.ts` re-exports `IRng`, and `src/units/spawn.ts` imports the RNG helpers from `@/common/rng`.
</objective>
