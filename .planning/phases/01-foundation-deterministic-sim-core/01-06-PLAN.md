<objective>
Retrofit the entire existing Phase-1 source (`src/sim/**`, `src/host/**`, `src/config/**`) AND `tests/**` to the user-locked project code-style conventions in `AGENTS.md` → `## Code Style Requirements (project-locked)`: D-13 (interface-first, `I` prefix, never use a class as a type), D-14 (numeric enums, no string-literal-union enums), D-15 (no `_` prefix on private members), D-16 (avoid inline types; unify to named interfaces).

Purpose: These conventions were added by the user AFTER Phase 1 executed (CONTEXT.md D-12..D-16) and are **project-level, long-lived, mandatory for ALL code**. They must be applied retroactively to the already-shipped Phase-1 tree, and they must become the conventions every later phase inherits. The retrofit is behavior-preserving: the determinism gate must be identical before and after.

Output: A tree where every class has an `I`-interface and implements it, no class is used as a type, command/event kinds are numeric enums, private members have no `_` prefix, and inline object types are named interfaces — with `pnpm run typecheck`, `pnpm run lint`, `pnpm test`, and `pnpm gate` all green.

**Atomicity (why two large tasks, not per-file) — scope-checker justification:** D-13 is a global rename graph — renaming `RngStream`→`IRngStream`, `EntityStore`→`IEntityStore`, `SimState`→`ISimState`, etc. changes every import and type position across production AND tests (`src/sim/world/world.ts` alone names five classes as field types). TypeScript does not compile a half-renamed graph, and the project rule is that the full suite stays green after every task (the pre-commit hook runs lint + the determinism gate). So each convention is applied as one globally-atomic task that updates all producers and consumers together. Per-file splitting would leave the tree typechecking-broken between tasks and is explicitly rejected here. The 23-file count is therefore a **deliberate, justified exception** to the per-plan file heuristic: the plan's calibrated estimate (55% of the context budget) already sits within budget, and correctness demands the atomic pass. See `scope_justification` in frontmatter.

**Reversibility note:** D-13 is user-locked `costly` — it touches every type declaration and reference (mechanical but project-wide). It was confirmed by the user in `01-CONTEXT.md`, so no `checkpoint:decision` is inserted. D-14/D-15/D-16 are `reversible`.
</objective>
