<objective>
Close GAP 1 (CR-01, critical): make the snapshot serializer **exhaustive** by serializing the entity-id cursor, and fold in the two cheap REVIEW hardening warnings that live in the same files (WR-03 int32 range guard in `snapshot.ts`, WR-02 exhaustiveness guard in `battle-sim.ts`).

Purpose: The phase's own must-have is "the serializer omits nothing" (Plan 01-04, threat T-01-04). `serializeState()` currently omits `EntityStore.nextId` and `restore()` reconstructs it as `max(live id)+1`; after `despawn(highest id) → snapshot → restore`, the next spawn REUSES a dead id, violating D-05 (ids stable/monotonic, never reused). This is latent through `BattleSim` today but immediately reachable via the public `sim.state.store` and via Phase 2's kill/respawn path — the exact churn path this phase exists to protect.

Output: A canonical, versioned, exhaustive snapshot that round-trips the id cursor; a proven regression (`spawn×2 → despawn(max) → snapshot → restore → spawn` yields the same id on both sims and never reuses a dead id); a completed mutator census; and two latent-hazard guards.

**Revising plan 01-04? No.** This plan does NOT rewrite 01-04; it corrects the specific omissions 01-04 left (the serializer was declared exhaustive but was not). 01-04's other deliverables stand.

**Reversibility note:** bumping the snapshot `VERSION` changes the canonical byte layout. No snapshot is persisted across sessions this phase (snapshots never leave the process), so this is a low-cost change — recorded as `costly` on Task 1 for traceability only; the user locked D-02's fingerprint contract already.
</objective>
