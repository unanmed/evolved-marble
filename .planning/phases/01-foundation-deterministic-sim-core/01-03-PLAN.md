<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| in-process state → serialized bytes → fingerprint | A serializer that omits state would let two divergent worlds report "equal". |
| developer → git commit | The gate must fail loudly on divergence (integrity guard). |
| fingerprint consumer | Must never treat the non-cryptographic hash as an authenticator. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-04 | Tampering / Repudiation | `serializeState`/`fingerprint` | high | mitigate | Exhaustive canonical serialization + `restore` round-trip test + mutator census ("every mutator moves the fingerprint") so no state-affecting field is omitted. |
| T-01-01 | Tampering | `src/sim/**` randomness/time | high | mitigate | Already enforced by Plan 01-02 lint + seeded streams; the gate here detects any regression that reintroduces nondeterminism. |
| T-01-03 | Spoofing | `fingerprint()` | low | accept | Documented in `snapshot.ts` as a diagnostic, never an authenticator (V6). |
| T-01-SC | Tampering | `pnpm install` of toolchain | high | mitigate | Covered and human-verified in Plan 01-01 (Task 2); no new installs in this plan. |

**Phase posture:** the gate is an integrity/diagnostic control, not a security boundary; snapshots never leave the process this phase (no untrusted-load threat).
</threat_model>
