<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| package registry → repo | Untrusted third-party code entering via `pnpm install` (bleeding-edge pins). |
| host pump → sim core | Only crossing into `sim/**`; must carry a step budget, never a wall-clock value. |
| seeded RNG → sim state | The sole permitted randomness source; any other source is a determinism (integrity) failure. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering | `src/sim/**` randomness/time sources | high | mitigate | All randomness through the seeded `RandomStreams` facade; no wall-clock read in `sim/**`; iteration only over `orderedIds` (Pitfall 4/5). Hard-linted in Plan 01-02. |
| T-01-SC | Tampering | `pnpm install` of toolchain | high | mitigate | Package Legitimacy Audit (all Approved) + blocking-human checkpoint (Task 2) + `npm view` pin re-verification (Task 1). Never auto-approvable. |
| T-01-03 | Spoofing | `fingerprint()` | low | accept | The hash is non-cryptographic and is documented in `snapshot.ts` as a diagnostic, never an authenticator (V6). No security decision will consume it. |

**Phase posture:** no network, no persistence, no user input this phase. The only real integrity risk is nondeterministic input leaking into sim state (T-01-01); the only supply-chain risk is the bleeding-edge install (T-01-SC).
</threat_model>
