**`src/control/DefaultUnitAI.ts`** (new): `export class DefaultUnitAI implements IUnitAI`. Deterministic, no `IRng` (D-15). Private `zeroAction()`, `nearestEnemy(observation)`, `isLowHealth(observation)`, `torqueToward(observation, dirX, dirY)`, `buildAction(observation, dirX, dirY, speed, skillIntent)` — all private with JSDoc. `(dirX, dirY)` is a **unit direction** supplied by the selector (toward the enemy for chase/attack, away for retreat), which keeps the helper unambiguous. The behaviour is a fixed priority selector (the full tree/skills are completed in 03-03):
1. no enemy → `zeroAction()`;
2. own `Health / MaxHealth <= DEFAULT_AI_LOW_HEALTH_RATIO` (treat non-positive `MaxHealth` as not-low) → call `buildAction` with the AWAY direction at `DEFAULT_AI_RETREAT_SPEED`;
3. otherwise call `buildAction` with the TOWARD direction, using `DEFAULT_AI_ATTACK_SPEED` when distance is at most `DEFAULT_AI_ATTACK_RANGE`, else `DEFAULT_AI_APPROACH_SPEED`.
Steering is velocity-error control: desired velocity = `(dirX, dirY) × speed`; `force = (desiredVelocity − motion velocity) × Mass × DEFAULT_AI_LINEAR_GAIN`; clamp the vector magnitude to `MAX_FORCE_MAGNITUDE`. Facing is PD: `angleError` is the wrapped angle to the direction, `torque = DEFAULT_AI_ANGULAR_GAIN × angleError − DEFAULT_AI_ANGULAR_DAMPING × motion.angularVelocity`, clamped to `MAX_TORQUE_MAGNITUDE`. `buildAction` decomposes signed `(fx, fy, torque)` into the six non-negative contract fields and sets `skillIntent: null` in this plan. This is intentionally a ram/lunge: the physical collision is what produces damage; the output contract has no separate attack field.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| AI plugin → ControlSystem | `IUnitAction` values are untrusted data returned by a replaceable plugin; `ControlSystem` is the sole execution boundary that validates and clamps them (ASVS V5). |
| ISensingWorld → Sensor | The world supplies ray distances and projectile sightings; malformed lengths, `NaN`, or out-of-range values cross into the observation. |
| Physics events → IDamageSink | `IDamageEvent`s and resolved `IUnit` references cross into upper-layer battle rules; a throwing sink can otherwise abort the tick loop. |
| ControlSystem → IPhysicsWorld | Force/torque application is the only actuator exit; an unclamped extreme value could eject a unit from the world. |
| (no network / no persistence) | The module is in-process only: no I/O, no secrets, no auth surface, no package installs. |
