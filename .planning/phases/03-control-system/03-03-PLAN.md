The decision structure is a FIXED PRIORITY BEHAVIOUR TREE expressed as private methods — a selector whose children are condition-guarded actions. Do not add node classes, a Status enum, an external BT library, or new types to `src/control/types.ts`; that preserves the frozen contract and avoids over-engineering.

**Private cooldown state** (one instance per unit, D-11; each field JSDoc'd): `bowReadyTick`, `arrowStormReadyTick`, `chargeReadyTick`, `spinReadyTick`, all initialized to 0 so a skill unlocked at spawn can fire on the first decision.

**Behaviour tree priority** in `decide`:
1. `nearestEnemy(observation) === null` → `zeroAction()`.
2. `isLowHealth(observation)` (Health / MaxHealth ≤ `DEFAULT_AI_LOW_HEALTH_RATIO`) → steer away from the nearest enemy at `DEFAULT_AI_RETREAT_SPEED`; no skill intent while retreating.
3. nearest enemy within `DEFAULT_AI_ATTACK_RANGE` → steer toward it at `DEFAULT_AI_ATTACK_SPEED` (a ram/lunge: the physical collision produces damage; the output contract has no separate attack field) and pass the result of `chooseSkillIntent(observation, distance)`.
4. otherwise → steer toward it at `DEFAULT_AI_APPROACH_SPEED` and pass the result of `chooseSkillIntent(observation, distance)`.

**`chooseSkillIntent(observation, distance): SkillIntent | null`** (private, JSDoc'd) — at most one intent per decision, in this order:
- A close-range unit skill inside `DEFAULT_AI_ATTACK_RANGE`: `SkillKind.Charge` when `observation.skills` contains it and `observation.tick >= chargeReadyTick` (then set `chargeReadyTick = observation.tick + CHARGE_COOLDOWN_TICKS`); otherwise `SkillKind.Spin` with `spinReadyTick`/`SPIN_COOLDOWN_TICKS`.
- `SkillKind.ArrowStorm` when unlocked, within `DEFAULT_AI_SKILL_RANGE`, and `observation.tick >= arrowStormReadyTick` (then arm `ARROW_STORM_COOLDOWN_TICKS`).
- A bow weapon intent when `observation.equipment` contains `EquipmentKind.Weapon` with `weapon === WeaponKind.Bow`, within `DEFAULT_AI_SKILL_RANGE`, and `observation.tick >= bowReadyTick` (then arm `BOW_SHOT_INTERVAL_TICKS`).
- Otherwise `null`. Every returned intent carries `observation.unitId`; use `SkillIntentKind.Unit` + `skill` for unit skills and `SkillIntentKind.Weapon` + `weapon` for the bow.

**Steering helpers** (private, JSDoc'd):
- `torqueToward(observation, dirX, dirY): number` — `(dirX, dirY)` is a unit direction; wrapped angle error to that direction, `DEFAULT_AI_ANGULAR_GAIN × error − DEFAULT_AI_ANGULAR_DAMPING × observation.motion.angularVelocity`, clamped to `MAX_TORQUE_MAGNITUDE`.
- `buildAction(observation, dirX, dirY, speed, skillIntent)` — desired velocity = `(dirX, dirY) × speed`; `force = (desiredVelocity − motion velocity) × Mass × DEFAULT_AI_LINEAR_GAIN`; clamp the force vector magnitude to `MAX_FORCE_MAGNITUDE`; decompose signed `(fx, fy, torque)` into `forceUp/forceDown/forceLeft/forceRight/torqueClockwise/torqueCounterClockwise` (all non-negative magnitudes) and set `skillIntent`. The selector passes the toward direction for chase/attack and the negated direction for retreat.
- `zeroAction()`, `nearestEnemy()`, `isLowHealth()` remain private with JSDoc. `isLowHealth` guards a non-positive `MaxHealth`.
- Use `AttributeKind.Health`, `AttributeKind.MaxHealth`, and `AttributeKind.Mass` from the observation; never read an `IUnit`.
- All numbers come from `src/control/constants.ts`; do not inline new magic values. Keep the implementation deterministic (no `IRng`, no `Date`).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| AI plugin → ControlSystem | A replacement `IUnitAIProvider`/`IUnitAI` is untrusted in-process code: its `decide` output and its exceptions cross into the simulation loop. |
| provider lifecycle → ControlSystem | `create`/`destroy` are plugin code; a throw here can leave registration or deregistration half-done. |
| AI → observation | The default AI must not be able to mutate physics or units; it consumes a pure snapshot only. |
| (no network / no persistence) | In-process only: no I/O, no secrets, no auth surface, no package installs. |
