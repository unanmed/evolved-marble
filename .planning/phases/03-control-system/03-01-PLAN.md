The `Sensor`, the `ControlSystem` loop, the `ArenaSensingWorld` test fixture, the `DefaultUnitAI` behavior tree, the `IDamageSink` integration, and the `src/control/constants.ts` values are ROUND-2 work, planned only after the user approves this contract. Purpose: this file is the frozen contract every unit AI and the Phase 4 kingdom world consume, so its shape is the phase's highest-value design artifact.
Output: `src/control/types.ts` (enum + interfaces + one union alias, JSDoc'd), `tests/control/types.test.ts` (numeric-enum pinning + compile-time contract assertions), and a resolved blocking-human design-approval checkpoint.

Contract shape carried from the locked decisions (present at the gate for confirmation):
- **D-01:** sensing is a CONTROL-layer seam (`ISensingWorld` + `ISensor`) that never extends or modifies the frozen `IPhysicsWorld`.
- **D-02:** 64 world-fixed rays (not body-relative), max 50 m; hits arena/map boundary + enemy units + reserved future obstacles; friendly units are never ray blockers.
- **D-03:** `IUnitBrief` carries only the documented neighbour fields (`unitId`, `health`, `level`, position, equipment); ≤16 after distance-ascending filtering; later additions are optional-only.
- **D-04:** `IProjectileSighting` is the reserved minimal projectile list (position + distance), Phase-3-empty.
- **D-05:** `IUnitObservation` is a pure per-decision data snapshot (attributes + motion + sensing) — the AI never touches Rapier, `IPhysicsWorld`, or `IUnit` mutators.
- **D-06:** registration binds `unitId ↔ IUnit ↔ teamId`; round 2 constructs `IUnitPhysicsSpec` from `IUnit` + the data tables. The contract declares `IControlUnitRegistration`.
- **D-07:** numeric `teamId` injected at registration, plus a reserved `updateTeam` runtime entry; `IUnit` is not modified.
- **D-08:** the sensing layer (not the AI) splits enemies/allies; `IUnitObservation.enemies`/`allies` arrive pre-classified.
- **D-09:** same-team units keep physical collision but deal no damage; the filter lives in the damage-application layer, never in physics.
- **D-10:** `IDamageSink` receives routed damage; `IControlSystem` routes but never owns battle rules.
- **D-11:** one `IUnitAI` per unit, created via `IUnitAIProvider.create(unitId, unit)` — the single pluggability seam.
- **D-12:** `IControlSystem.tick()` drives decide→apply→`physics.tick()`→route-damages; cadence is tick-counted, not wall-clock.
- **D-13:** `IUnitAction` is four world-axis force magnitudes + two torque directions + a skill intent; the held action is re-applied every physics tick and skill intent fires once per decision tick.
- **D-14:** the decision is a pure function over the snapshot (behavior tree is the round-2 default structure).
- **D-15:** no determinism is claimed; the default baseline AI is deterministic and injects `IRng` only if a test needs randomness.
- **D-16:** the default baseline AI is a validation-only stub (chase/attack/retreat), replaced later — round 2.
- **D-17:** weapon/unit skills are intent + cooldown ONLY in Phase 3; no projectile/charge/spin physics.
- **D-18:** `AttributeKind.ControlLevel` does not drive default-AI strength in Phase 3; the Provider is the future per-level selection seam.
- **D-19:** the frozen physics registration snapshot (WR-01) stays accepted; the AI reads live `IUnit` attributes but physics damage keeps the registration-time snapshot.
