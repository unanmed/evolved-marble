## 时间系统与 tick 映射

| Option | Description | Selected |
|--------|-------------|----------|
| 固定 60Hz | 1× 每 tick 1 游戏分钟；24× 每 tick 24 游戏分钟 | |
| 固定 1 游戏分钟/tick | 24× 提高 tick 频率 | |
| 可变 tick 率 | 1× 60Hz / 24× 2.5Hz | |

**User's choice:** 自由回答 —— 「模拟层面并没有 tickrate 的概念，一个 tick 完全可以推理好几秒……不加速的时候，1 tick 就是一分钟，加速的时候，1 tick 就是 24 分钟，文档里面明明写的非常清楚」
**Notes:** 无 wall-clock tickrate；1× 1 游戏分钟/tick，24× 24 游戏分钟/tick；所有计时按游戏时间；成片由 WebCodecs 处理。

## 战斗区重叠/增援 + 战后结算

| Option | Description | Selected |
|--------|-------------|----------|
| 加入并合并 | 新军队进入即加入；重叠合并 | |
| 保持独立战斗 | 单位可同时属于多场 | |
| 禁止重叠 | 新战斗等现有结束 | |

**User's choice:** 自由回答 —— 「单位本身是永久模拟的，任何单位只要进入范围，就直接加入战场，跟军队本身没有任何关系，军队只是多个单位组成的宏观概念，在战斗层面并没有军队的概念」
**Notes:** 战斗是单位级；任何单位进入 80m 即加入；军队只是宏观容器；重叠按同一战场处理。

| Option | Description | Selected |
|--------|-------------|----------|
| 保留原军队，灭队则重组 | 存活单位保留 armyId | |
| 自动归入最近己方军队 | 按位置合并 | |
| 单位独立，指挥官重编 | 战后重新编组 | |

**User's choice:** 自由回答 —— 「战斗双方保留原军队，彼此相距 80m 后才可以再次发生战斗，避免重复触发」
**Notes:** 保留原 armyId；>80m 才能再次触发。
