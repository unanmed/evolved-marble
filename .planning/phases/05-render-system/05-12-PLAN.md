   - `readonly zoomFrames: number;` — JSDoc: frames spent zooming to the target scale after the pan.
   Keep all other fields byte-identical (the rest of the contract is frozen).
2. `src/render/constants.ts`:
   - `CAMERA`: `panFrames: 24`, `zoomFrames: 6`, `shakeAmplitudePx: 0`, `minSpanMeters: 12`; remove `switchFrames`.
   - `validateRenderConfig`: replace the `switchFrames` assertion with `assertAtLeast('camera.panFrames', ...)` and `assertAtLeast('camera.zoomFrames', ...)`; keep all other validations.
3. `src/render/Camera.ts`: replace `transitionTotal`/`transitionRemaining` with a single elapsed-frame counter driven by `update()`.
   - `setBattleTarget` snapshots the current transform and resets elapsed to 0; `mode` becomes `BattleFocus` immediately for a numeric target.
   - In `update()` while transitioning:
     - Phase 1 (`elapsed < panFrames`): pan centre from the snapshot to the CURRENT target centre, scale held at the snapshot scale, eased; `alpha = panFrames <= 1 ? 1 : elapsed / (panFrames - 1)` (so the first update is t=0).
     - Phase 2 (`elapsed >= panFrames`): centre fixed to the target centre, scale eased from the snapshot scale to the target scale; `beta = zoomFrames <= 1 ? 1 : (elapsed - panFrames) / (zoomFrames - 1)`.
     - On `elapsed >= panFrames + zoomFrames - 1`: snap exactly to the target transform, clear the transition, and set `mode` from the target id (Strategic when undefined).
     - Increment `elapsed` once per update.
   - Keep the shake accumulation/clamping code; with amplitude 0 it produces zero offset.
   - Non-transition steady state keeps using `trackTransform`.
4. Update `tests/render/camera.test.ts` and `tests/render/constants.test.ts` for the new field names and durations. Add assertions that:
   - the first pan frame keeps the start scale,
   - scale only starts changing at/after `panFrames`,
   - the last update lands exactly on the target,
   - pulling back to strategic still stays in `BattleFocus` until completion.
