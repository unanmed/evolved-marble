Create `src/render/cameraMath.ts` with a header JSDoc: pure functions only, no Pixi, no class, no state, no wall-clock, no randomness. Import types from `@/render/types` only.

Export and JSDoc:

1. `lerp(a: number, b: number, t: number): number` — guarded linear interpolation; a non-finite `t` falls back to `a`.
2. `smoothstep(edge0: number, edge1: number, x: number): number` — returns 0 below `edge0`, 1 above `edge1`, cubic Hermite in between; when `edge1 <= edge0` return the step (`x >= edge1 ? 1 : 0`) so the HUD model cannot divide by zero.
3. `easeInOutCubic(t: number): number` — clamp `t` to [0,1], then the standard two-branch cubic.
4. `fitBox(points: readonly IVec2[], coverage: number, minSpanMeters: number): IFitBox | null` — drop non-finite points first; return `null` when none remain. Compute `cx`/`cy` as the median of the finite x/y arrays (even count averages the two middle values). Compute each point's Chebyshev distance `max(|x-cx|, |y-cy|)`, sort ascending, clamp `coverage` into `(0,1]`, set `rank = clamp(ceil(coverage*n) - 1, 0, n-1)`, `halfSpan = max(distances[rank], minSpanMeters/2)` and, if `halfSpan` is not finite, fall back to `minSpanMeters/2`. Return `{minX: cx-halfSpan, maxX: cx+halfSpan, minY: cy-halfSpan, maxY: cy+halfSpan}`.
5. `strategicTransform(bounds: IMapBounds, viewport: IViewport, config: ICameraConfig): ICameraTransform` — guard non-finite/non-positive bounds and viewport (fall back to centre `(0,0)`, scale 1). `usableW = max(1, width - 2*paddingPx)`, `usableH = max(1, height - 2*paddingPx)`, `scale = min(usableW/bounds.width, usableH/bounds.height)` clamped to `(0, maxScale]`; centre is the map centre; shake offsets are 0.
6. `fitTransform(box: IFitBox, viewport: IViewport, config: ICameraConfig): ICameraTransform` — guard non-finite box (fall back to a `minSpanMeters` square at the origin). `spanX`/`spanY` are at least `minSpanMeters`; `fit = min(usableW/spanX, usableH/spanY)`; `scale = clamp(fit, minScale, maxScale)`; centre is the box centre; shake offsets are 0.
7. `trackTransform(current: ICameraTransform, target: ICameraTransform, config: ICameraConfig): ICameraTransform` — `alpha = 1 - exp(-1 / max(1, smoothingFrames))`; centre components lerp; scale interpolates in log space (`exp(lerp(log(current.scale), log(target.scale), alpha))`), guarding non-positive scales; shake components are 0 because Camera owns them.
8. `interpolateTransform(from: ICameraTransform, to: ICameraTransform, t: number): ICameraTransform` — clamp `t`; lerp centres, log-space scale; shake 0. At `t = 1` the result equals `to` component-wise (within floating-point tolerance).
9. `worldToScreen(point: IVec2, transform: ICameraTransform, viewport: IViewport): IScreenPoint` — `x = viewport.width/2 + (point.x - transform.centerX) * scale + shakeX`, the same for y; guard a non-positive/non-finite scale by returning the viewport centre.
10. `screenToWorld(point: IScreenPoint, transform: ICameraTransform, viewport: IViewport): IVec2` — the exact inverse, subtracting the shake offsets; guard non-positive scale by returning the camera centre.

The world y axis is deliberately NOT flipped, so a physics angle can be used directly as a container rotation (research §6). State that in the `ICameraTransform`-consuming JSDoc.
