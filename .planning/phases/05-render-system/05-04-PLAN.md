<objective>
Implement `src/render/frameModel.ts` — the pure per-frame projection from simulation state to render vocabulary — together with the shared test fakes and two test suites. This is where REND-02 becomes data: a unit's faction colour, weapon and armours are resolved through the frozen numeric enums, and the camera's participant point set and the renderer's culling decision become plain functions.

Purpose: the renderer should never contain a branching decision about *what* a unit looks like or *whether* it is on screen; it should only write the resulting numbers into Pixi properties. Keeping those decisions here makes the weapon/armour coverage testable against the real Phase 1 tables (including the Hammer/Helmet pair the default scenario lacks) and gives 05-05's damage tap a reusable set of narrow fakes.

Output: `src/render/frameModel.ts`, `tests/render/fakes.ts`, `tests/render/frame-model.test.ts`, `tests/render/visual-spec.test.ts`.
</objective>

Then create `src/render/frameModel.ts` with a pure-module header JSDoc (no Pixi, no Rapier, no class, no state). Import `FALLBACK_FACTION_COLORS` from `@/render/constants`, types from `@/render/types`, `IBattle`/`IVec2` from `@/kingdom/types`, and `EquipmentKind` (value) plus `IUnit` (type) from `@/units/types`.

Export and JSDoc five functions:

1. `resolveFactionColor(factionId: number | undefined, factionColors: Readonly<Record<number, number>>, neutralColor: number, fallbackColors: readonly number[] = FALLBACK_FACTION_COLORS): number` — return the configured colour when `factionId` is a finite integer and the table has an own entry whose value is a finite integer in `[0, 0xffffff]`; when the id is finite but unconfigured, index `fallbackColors` with `Math.abs(Math.trunc(factionId)) % fallbackColors.length` (guarding an empty list); when the id is absent/non-finite or no valid colour exists, return `neutralColor`. Never return `undefined`.
2. `resolveUnitVisualSpec(unit: IUnit, factionColor: number): IUnitVisualSpec` — iterate `unit.getEquipment()` once: the first entry with `kind === EquipmentKind.Weapon` and a defined `weapon` becomes `weapon`; every entry with `kind === EquipmentKind.Armor` and a defined `armor` is appended to `armors` in encounter order. `classKind` comes from `unit.getClass()`. Return `{ factionColor, classKind, weapon, armors }`.
3. `resolveUnitViewSpec(unitId: number, unit: IUnit, factionColor: number): IUnitViewSpec` — `{ unitId, visual: resolveUnitVisualSpec(unit, factionColor) }` (the caller snapshots it once).
4. `resolveTargetPoints(battle: IBattle, getUnitState: UnitStateLookup): readonly IVec2[]` — iterate `battle.getMemberUnitIds()` in order, call `getUnitState(id)`, skip `null` and skip any non-finite `x`/`y`, and return the collected `{ x, y }` points (empty array allowed).
5. `isUnitVisible(query: ICullQuery): boolean` — return `false` if `scale`, `viewport.width`, `viewport.height`, `x`, `y` or `marginMeters` is non-finite, or `scale <= 0` or a viewport dimension `<= 0`; treat a negative margin as 0; otherwise compute `halfW = viewport.width / (2 * scale) + margin` and `halfH = viewport.height / (2 * scale) + margin` and return `Math.abs(x - centerX) <= halfW && Math.abs(y - centerY) <= halfH`.

Then create `tests/render/frame-model.test.ts` (`describe('render/frame-model — …')`) using the fakes. Cover: `makeUnitState` values flow through `resolveTargetPoints` unchanged; member order preserved; a member whose lookup is `null` is skipped; a member with NaN coordinates is skipped; an empty member list yields `[]`; faction colour resolution for a configured id, an unconfigured id (deterministic fallback, repeat call identical), an absent id (`undefined` → neutral), an empty fallback table (→ neutral), and a malformed table value (→ neutral); culling: point at the viewport centre visible, point just inside `halfW + margin` visible, point just outside it hidden, boundary equality visible, NaN x hidden, `scale: 0` hidden, zero-size viewport hidden, negative margin treated as 0.

Format both files to `.prettierrc`.
